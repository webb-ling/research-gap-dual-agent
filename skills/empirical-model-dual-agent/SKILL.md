# 实证模型建立与核验双 Agent Skill

输入为研究问题、前一环节的候选空白、使用者的初步模型和可获得的数据文档；可选输入为实际数据文件。先保留初稿，再由建模 Agent 提出修订方案，检验 Agent 独立挑错，建模 Agent 根据意见逐条修订，最后由使用者确认。

## 当次配置

1. 主 Agent 梳理研究对象、分析单位、变量、样本、目标参数和拟采用的模型。阅读 [动态提示词模板](references/agent-prompts.md)，把当次主题、数据来源、初稿、限制及可用工具填入两名 Agent 的任务。
2. 盘点实际连接的官方数据页面、文件工具、统计软件和 `research-workflow-tools` MCP。MCP 提供 `check_model_plan`（方案字段与显见矛盾检查）；仅在使用者提供本地 CSV 时使用 `profile_csv_variables`（缺失及类别分布）和 `count_group_cells`（分组组合计数）。工具参数格式见 [模型方案与工具输入](references/model-plan-schema.md)。未连接或未提供数据时不声称调用过这些工具。
3. 在支持子 Agent 的环境中创建建模 Agent 与独立检验 Agent；否则按两种独立角色顺序执行并保留各自输出。检验 Agent 只提交问题、依据和建议，不直接改写建模 Agent 的方案。

## 审查与迭代

- 建模 Agent 用原始问卷、代码本及数据说明核对指标含义、跳题和覆盖范围；提出样本筛选、缺失处理、变量编码、控制变量、模型公式和估计目标。权重、固定效应、聚类与交互项的处理应由数据结构和研究问题支持，不能机械套用。
- 检验 Agent 独立检查变量是否对应问题、样本是否合格、模型是否回答异质性问题、系数解释是否正确，以及哪些事项必须获得数据后才能判断。对于 Logit 交互，不能把交互系数直接当作概率差；应考虑调整预测概率或其他适合目标参数的量。
- 主 Agent 把每条审查意见交给建模 Agent，要求标明“采纳／不采纳／待数据验证”及理由，再由检验 Agent 复核关键修改。证据不足时留下待核实项；不要声称已经估计、检验显著性或完成实际未执行的迭代。

## 交付

提供初步方案与修订方案的对照、变量和符号定义、样本与估计目标、最终拟议模型公式、审查清单及修订记录、实际使用的工具、尚需数据验证的问题。明确区分相关性描述与因果结论。没有数据时输出的是可执行的建模方案，不是已证实“正确完整”的模型。
