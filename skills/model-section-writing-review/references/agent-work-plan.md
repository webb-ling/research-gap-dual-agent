# Model setup Agent 工作安排

版本：v1

本安排采用素材检查 Agent、写作 Agent、审核 Agent 三类主要角色。写作 Agent 可按任务创建子 Agent。各角色共同完成用户已确定模型的论文表达，不自行增加、替换或优化模型。当前范围仍限于模型信息，不展开具体数据处理与实际估计结果。

本文规定角色与交接，不代表已启动这些 Agent 或已开始改写用户模型。

## 共同依据

- information-checklist.md：判断素材信息是否齐全、明确且一致。
- writing-framework.md：组织信息、公式和段落。
- material-request-format.md：处理缺失、不明确和冲突。
- 本安排：规定谁检查、谁提问、谁写作、谁审核，以及意见如何闭环。

前三份标准及本安排都是流程配置。运行中仍只维护素材文档与结果文档两份工作文档。

## 主要角色

| 角色 | 核心责任 | 主要输入 | 主要输出 | 文档权限 |
| --- | --- | --- | --- | --- |
| A 素材检查 Agent | 检查素材、提出最小补充请求、整理用户回答、判断是否可进入写作 | 当前素材、信息检查表、请求格式、写作或审核阶段退回的素材问题 | 检查记录、用户补充请求、当前确认素材、通过或未通过状态 | 维护素材文档；读取结果文档；不改写成稿 |
| W 写作 Agent | 建立信息与段落关系、分配写作、整合全文、回应审核意见 | 通过检查的当前素材版本、标准文稿框架、审核意见 | 信息与段落对应表、文稿、修改说明、提交审核的版本 | 读取素材文档；维护结果文档；不修改已确认模型 |
| R 审核 Agent | 独立检查当前文稿，提出具体问题，复核修改是否解决问题 | 与文稿对应的素材版本、检查表、框架、当前结果版本、上轮意见及回应 | 逐项审核记录、问题清单、复核结论 | 两份文档均只读；将意见返回W和A，不直接改写素材或正文 |

宿主负责调度和传递消息，不另增一个决定模型内容的角色。子 Agent 的提问意图由 A 汇总后，经当前对话统一向用户提出；不让多个角色同时向用户索取同一信息。

## A 素材检查 Agent

### 工作顺序

1. 阅读完整素材、已有补充和未解决请求，识别当前采用的模型版本。
2. 逐项应用信息检查表，记录“满足／缺失／不明确／冲突／不适用”及素材依据。
3. 区分真正的信息缺口和表达问题。若信息已能从素材或公式唯一确定，记录依据，不向用户重复提问。
4. 将真实缺口按依赖关系分组，使用既定请求格式提问；同一个缺口只建立一个请求。
5. 用户回答后，保留原话，整理当前确认内容，记录替代关系，重查受影响的条目。
6. 所有必需项及适用条件项均满足时，将当前素材版本交给 W；否则保留明确的未完成状态。

### 向 W 的交接

- 当前素材版本及其定位方式。
- 每项信息对应的位置，及不适用项的理由。
- 当前采用的公式、符号定义、模型对象、解释边界和关键作者决定。
- 模型信息的检查结论。存在必需缺口时，不发出可开始完整成稿的通过结论。

### 权限边界

A 可以整理、定位和清晰转述用户已经确定的内容，可以解释公式唯一确定的数学含义。存在会改变模型含义的选择时，应请求用户决定。不得将建议、候选解释或自己的推测写成作者已确认的模型。

用户回复清楚时直接更新，不再追加一次形式确认。用户修改模型时，保留旧记录并明确当前采用内容。

## W 写作 Agent

W 是全文负责人。它可以拆分任务，但对信息覆盖、符号一致和最终行文承担完整责任。

### W1 信息与段落规划子 Agent

输入：当前确认素材、通过检查的信息条目、标准文稿框架。

工作：

- 将每个适用信息条目安排到功能单元和具体段落。
- 确定首次定义位置、公式位置、叙述次序以及哪些内容应合并。
- 给每段规定要传达的信息、可用依据和上下文，不只分配一个空泛主题。
- 检查是否有遗漏、重复安排或需要返回 A 的真实缺口。

输出：信息与段落对应表、段落顺序、统一符号和术语约定。

对应表采用以下字段：

| 段落编号 | 段落功能 | 对应检查项 | 素材位置 | 本段要传达的具体信息 | 与前后段的关系 |
| --- | --- | --- | --- | --- | --- |
| 待填写 | 目的／公式／定义／设定／参数解释 | 待填写 | 待填写 | 待填写 | 待填写 |

### W2 要素写作子 Agent

W2 是可创建多个实例的任务角色。按信息复杂程度分配目的与对象、公式与符号、关键设定、参数与研究问题等任务，不机械地为每一句话创建一个 Agent。

每个实例均接收同一版确认素材、全文规划和符号约定，另有明确的负责段落。

工作：

- 将指定信息写成准确、简洁、含义充分的论文句子。
- 保留条件、参照组、尺度和限制，不以删减这些内容换取简短。
- 使用完整上下文避免重复定义、前后术语不一致或错误衔接。
- 每个有实质含义的表述均能定位到素材，或说明其为基于已确认公式的直接数学解释。

输出：负责段落的文本、内容与素材的对应、发现的问题。

发现信息不足时向 W 报告，W 转 A 处理。W2 不直接询问用户，不用猜测填补缺口，不直接写入正式结果正文。

### W3 全文衔接子 Agent

输入：段落规划、W2返回的文字、当前确认素材和统一符号约定。

工作：

- 使各部分成为连续文稿，调整局部顺序与连接句。
- 合并重复内容，统一术语、符号、句式和叙述视角。
- 检查首次定义与后文使用的关系，避免突然引入新符号或新比较对象。
- 精简空话和重复，但保留模型解释所需条件。
- 若整合需要新增实质内容或改变模型，应报告给 W，而非自行补写。

输出：整合稿及实质性调整说明，不代替 R 的独立审核。

### W 的整合与提交

1. 核定 W1 规划，再派发 W2 任务；彼此独立的段落任务可并行。
2. 收齐段落并处理冲突后，交 W3 做全文衔接。
3. 对整合稿进行自查，核对公式和符号，并确认适用信息已覆盖。
4. 由 W 统一写入结果文档，标明所依据的素材版本、稿件版本及待审核状态。
5. 向 R 提交文稿、信息与段落对应表及本轮修改说明。

简单模型可以由 W 自行承担部分或全部子任务。子 Agent 的数量按实际复杂度和宿主并发能力调整；规划、整合与审核遵循先后依赖，不宣称本不能并行的步骤已并行。

## R 审核 Agent

R 独立阅读原始确认素材和成稿，不能仅依赖 W 声称已经覆盖的信息表。审核的是文稿是否充分、忠实且清楚地表达已确认模型，不替用户评选更优模型。

### 审核维度

| 维度 | 检查内容 |
| --- | --- |
| 信息完整 | 适用检查项均在正文有实际表达；对应表中标了覆盖但正文未表达的内容仍算遗漏。 |
| 内容忠实 | 未增加作者没有确定的设定、动机、假设、结果或更强结论；直接数学解释具有可核对的依据。 |
| 数学与符号一致 | 公式、定义、下标、取值、参照组及全文使用一致；必要条件和解释尺度正确。 |
| 问题对应 | 研究目的、模型结构、目标参数或比较量、判断逻辑相互对应。 |
| 行文清楚 | 定义及时，句子含义明确，段落顺序和衔接有助于理解，读者无需查看内部记录才能读懂正文。 |
| 简洁充分 | 无明显空话、重复或不必要展开，同时不因压缩丢失关键条件和含义。 |
| 范围合适 | 保留必要模型定义，未擅自扩展到具体数据处理、结果分析或新的研究任务。 |

这是一组检查维度，不采用无依据的综合分数。审核问题必须给出位置、依据和实际影响，不能只提出“更学术”“再润色”等笼统要求。

### 问题清单格式

| 问题编号 | 所审素材与稿件版本 | 位置 | 关联条目或维度 | 问题及依据 | 对读者理解或模型含义的影响 | 修改方向 | 类型 | 是否阻止通过 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 待填写 | 待填写 | 待填写 | 待填写 | 待填写 | 待填写 | 待填写 | 写作问题／素材问题 | 是／否及理由 |

R 可以给局部措辞建议或指出应表达的含义，但不直接接管改写，也不以自己的候选模型替换用户模型。

明确遗漏、内容失真、数学解释错误、影响理解的歧义或适用范围越界应阻止通过。纯偏好性的措辞建议不阻止通过，应明确标为建议，避免无休止地更换近义表达。

## 审核后的循环

### 写作问题循环

适用：素材已经充分，但正文漏写、错写、重复、衔接不清或不够简洁。

1. R 向 W 返回具体问题。
2. W 逐条记录“已采纳修改／未采纳并说明依据／需返回素材确认”，必要时重新分配子任务。
3. W 修订正文并提交新版本，标出修改位置和对应问题。
4. R 复核原问题是否解决，并检查修改是否造成其他矛盾。
5. 对未采纳事项，由 R 根据素材和标准判断是否关闭；W 不能仅凭自己认为已完成就关闭审核问题。

### 素材问题循环

适用：写作或审核中发现确认素材仍缺少必要信息、含义不明确或存在冲突。

1. W 或 R 将具体位置、问题和影响交给 A。
2. A 先重新检查全部素材，确认不是已有内容漏读或文稿表达问题。
3. 若确实需要用户决定，A 按既定格式提问，维护同一请求记录。
4. 用户回复后，A 更新素材及检查状态，形成新的确认版本。
5. A 向 W 说明哪些定义、公式或段落可能受影响；W 更新对应表和文稿。
6. R 使用新的素材版本复核受影响内容。旧审核结论不能自动当作新版本已通过。

必需素材尚未补齐时，保留已有结果文稿但标明等待补充，不输出为已通过版本。待补充期间不以猜测填空。

## 两份工作文档的内部安排

| 文档 | 内容区 | 维护角色 |
| --- | --- | --- |
| 素材文档 | 上传原稿、用户补充原话、当前采用内容及替代关系、检查表状态、素材请求记录、素材版本 | A |
| 结果文档 | 当前文稿正文、信息与段落对应表、稿件版本与所依素材版本、审核问题、逐条修改回应和最终状态 | W |

R 返回的意见由 W 写入结果文档的工作记录区；确属素材问题的请求由 A 在素材文档中维护并通过编号关联，避免产生相互矛盾的两份记录。

所有子 Agent 读取同一版素材和任务说明，只返回任务成果。正式文档分别由 A 和 W 统一更新，避免多个角色同时覆盖文件。内部记录与最终正文分区；面向用户交付时默认只呈现通过审核的正文，过程记录仍可追溯。

## 版本与完成条件

- 每次交接同时标明素材版本和稿件版本，审核结论只适用于明确的版本组合。
- 用户在运行中修正模型时，A 更新当前采用内容，W 调整相关文稿，R 重新核对受影响内容。
- 审核中如发现参考标准本身存在会影响判断的冲突，由宿主明确提出，不默默替换标准或据此修改模型。
- 所有必需信息满足，文稿覆盖适用条目，阻止通过的问题均关闭，且 R 对当前版本给出通过结论后，才输出为通过稿。
- 不以达到固定修改轮数、多个 Agent 意见一致或文字越来越短作为自动通过依据。
- 最终通过表示 model setup 的信息传达达到标准，不表示模型已完成理论或统计验证。

## 一次完整运行的顺序

1. A 检查当前素材，必要时向用户请求补充并循环。
2. A 交接通过检查的确认素材。
3. W 组织 W1 建立信息与段落关系。
4. W 分配 W2 完成各部分文字，必要时并行。
5. W 组织 W3 整合衔接，自查后形成结果文稿。
6. R 独立审核并返回逐项意见。
7. 写作问题回 W，素材问题回 A；修改后重新交 R 复核。
8. R 确认当前版本通过，W 输出正文并保留工作记录。
