# 文稿审核标准

对照当前确认素材审核文稿，所有意见必须落到位置、依据和实际影响。依据包括本 Skill、信息检查表、文稿框架，以及用户已确认的模型信息。

| JSON维度键 | 指标 | 满足条件 |
| --- | --- | --- |
| coverage | 信息完整 | 信息检查表中当前适用的必要信息均由公式与正文实际传达；可合并表达，不要求每项对应独立句子或段落，不以段落规划中的勾选代替正文。 |
| fidelity | 内容忠实 | 未加入未经用户确定的模型、变量、假设、作者动机或更强主张；直接数学解释可定位到公式。 |
| math | 数学与符号一致 | 公式、符号、下标、取值、参照组、条件及解释尺度正确且一致。 |
| alignment | 问题对应 | 研究目的、模型结构、目标参数或比较量和判断逻辑一致。 |
| clarity | 行文清楚 | 概念及时定义，句意明确，段落衔接自然；不查看内部记录也能读懂。 |
| conciseness | 简洁充分 | 目的、定义、核心释义和解释边界各在所需位置表达，无明显重复、空话或无助于核心问题的推导；可删除或合并而不损失独立必要信息的内容已精简，且未丢失条件与含义。 |
| scope | 范围合适 | 保留模型定义及边界，未擅自展开数据处理、结果或新研究任务。 |

每个维度返回 ok 和 evidence，后者指出正文的具体对应或不足。只有纯偏好性建议时，维度可以为通过，并将建议记为 blocking=false。维度不通过时，应至少有一个阻止通过的问题，并在该问题中列出 dimensions 对应键。

问题条目包含 kind（writing或material）、blocking、location、basis、impact、direction，并可加稳定 id、dimensions 和所关联的信息检查项。素材已有而正文漏写不能标为素材问题。

以下问题阻止通过：必要信息遗漏、模型内容失真、数学或参数解释错误、影响理解的歧义、与作者确定范围不符的新增主张，以及反复解释同一内容或无关展开而明显拖长正文。冗长意见须指出可删并的位置及其与已保留信息的重复关系，不能仅因超出偏好的字数或段数判定失败。非阻止性建议不能掩盖这些问题。

不为补齐框架形式、逐项列出全部系数的等价含义或增加教程式推导要求扩写。需要补充时，指出实际缺少的独立信息及其对理解的影响，优先建议在已有句子中补足。

R 复核旧问题的关闭情况，不能以 W 已回应、达到某个轮数或多个角色一致作为通过依据。若参考规范发生变化或相互矛盾，应明确报告，不静默采用新口径。
