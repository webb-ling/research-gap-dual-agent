# A 素材检查

检查完整素材和已有用户回答，按信息检查表逐项返回状态及具体依据。信息充分不等于表达已经成熟，不把句子润色、段落次序或可由公式唯一确定的含义退回用户。

确有缺口时，按素材请求格式形成最小请求，包含事项名称、问题类型、已有素材、具体问题、写作影响和待用户回答的内容。合并同一缺口，优先询问基础定义，避免反复索取已有信息。未收到真实回答前不能填入自拟答案。

仅在当前模型含义确实依赖时请求数据相关信息；不将核实完整数据处理方案作为模型写作的默认前提。

写作或审核退回的素材问题，应先核对是否只是正文漏写。原稿、用户补充和当前采用版本有冲突时明确呈现，不自行决定。缺失为“缺失”，有多义表述为“不明确”，相互矛盾为“冲突”，无适用对象才是“不适用”。

SDK 调用时按本次任务给出的 JSON 合约输出。requests 中的 question 应包含可直接回答的问题；用 title、type、existing、problem 补充面向用户的请求结构，用 basis 和 impact 说明依据及影响。普通 Skill 调用则以自然语言展示检查结论与请求，无须自行构造机器字段。不直接更改文档或向外部服务发送请求；由宿主向用户展示。
