# Model setup 标准文稿框架

版本：v2

将用户确认的模型草稿写成信息充分、表达紧凑的论文正文。以用户提供的简洁试写为本次风格基准：直接引出模型，集中定义符号，简要交代目标量及其比较方式。信息检查表用于保证信息齐全，不是逐项展开的正文提纲；一项信息不必占一句话，一个功能不必占一段。

## 范围与参考

保留研究目的、对象范围、完整公式、必要符号定义、关键设定及目标量的解释。暂不展开数据来源、筛选、匹配、缺失处理、缩尾、实际样本量、权重实施步骤、软件、估计算法或实际结果。变量取值、参照组、尺度与变换属于模型定义；已确认且直接界定目标量的权重口径、推断口径可用短句交代，不延伸到操作细节。

原参考论文提供以下组织方式，本框架据此安排信息，不移植其模型选择、变量或因果措辞：

| 参考论文 | 原文位置 | 借鉴方式 |
| --- | --- | --- |
| 技术创新与企业韧性：基于新冠疫情情景，贾勇等 | 3.2、3.3节，正文第23—25页 | 以检验目的引出方程，围绕公式集中解释变量与模型项。 |
| 工业机器人应用、性别工资差距与共同富裕，许健等 | 第三部分第2小节，正文第141—142页 | 列式后解释下标、核心变量及参数的经济含义，交代组间比较。 |
| ESG的就业效应研究：来自中国上市公司的证据，毛其淋等 | 第三部分第1小节，正文第90页 | 用研究目的引出模型，将变量和核心系数对应到研究问题。 |

设定依据或作者选择理由仅使用确认素材；这些参考论文不自动成为当前模型的理论或文献依据。

## 默认正文结构

对单一主方程及常规交互项模型，优先采用三个文字段落加一个公式单元；不另设“变量说明”“关键设定”“参数解释”等小标题。复杂模型可按独立信息增加段落，不按检查项数增加篇幅，也不设统一字数配额。

| 位置 | 要传达的信息 | 写法与检查项 |
| --- | --- | --- |
| 第1段：目的与设定 | 研究谁、关注何种关系或比较、采用什么模型 | 通常一至两句引出公式；覆盖 Q1、Q2、O1，O2 按需。无须重述研究背景或再次预告后文。 |
| 公式单元 | 用户确认的完整模型 | 紧接引导句列式；覆盖 M1。多方程时说明用途和关系，覆盖 M2。 |
| 第2段：符号与核心含义 | 下标、变量、取值、参照组、其他模型项及必要参数解释 | 依公式顺序集中定义；把关键设定的作用或核心系数含义接在相关定义后，不再另写一段重复解释。覆盖 S1—S3、R1，R2 与 O2 按需；可同时覆盖 P1、P2。过长时可拆段。 |
| 第3段：目标量与比较方式 | 用什么量回答问题，按什么条件、尺度与基准比较 | 只补充上一段尚未交代的目标量、比较规则与必要解释边界；覆盖 P1—P3。已有解释不再复述；若前文已充分传达，可合并或省去独立段落。 |

## 连续文稿骨架

以下展示信息顺序，不要求原样套用句式：

> 本文考察〔对象范围〕中〔核心关系及比较问题〕，设定以下〔模型类型及关键结构〕：
>
> 〔用户确认的完整公式〕
>
> 其中，〔下标与变量定义，必要取值、参照组及控制项〕。〔其余模型项及核心参数的必要含义，直接注明解释尺度和比较基准〕。
>
> 本文关注〔目标量或派生比较量〕，通过〔共同条件下的比较方式〕回答〔尚未在前文表达清楚的具体问题〕。〔必要且已有依据的推断口径或解释边界〕。

最后一段的占位项按实际需要取用，不能为了填满骨架补写模型选择或重复研究目的。

## 精简时的取舍

1. **同一信息只表达一次。** 研究目的放在开头；变量定义集中在公式后；目标量与比较方法就近说明。结尾不再用总结句重复前三者。
2. **直接交代含义。** 优先写“某参数表示某基准下的差异”，删去“为便于读者理解”“需要进一步明确”“接下来分别说明”等引导语。不逐句讲解标准模型的常识。
3. **区分定义和推导。** 定义所有影响理解的模型项，但只展开回答研究问题所需的参数含义。允许合并同类参数说明；不要求逐一列举所有代数等价式、组别方程或反向比较。
4. **解释必要的尺度差异。** 例如 Logit 交互系数与概率差异应区分，可在系数释义中注明“在对数优势尺度上”，再直接给出概率比较方法；不必另用一段重复论证二者不同。必须保留防止实质性误读的条件。
5. **比较规则用文字说清即可。** 已确认的预测概率或组间差异通常可用一至两句表达；只有文字不足以唯一界定目标量，或用户要求时，才增加派生公式和符号。
6. **边界就近交代。** 必要的关联或因果边界可用一句准确措辞表达，不在开头、系数解释和结尾反复声明。已确认的设定理由有助理解时简述，不为每项设定另建论证段。
7. **先保证含义，再压缩。** 不删改作者模型、变量定义、适用范围、比较基准或解释尺度。真正缺少素材时交 A；仅需合并或删重时由 W 处理。

## 角色执行与交付

- W1 将多个信息项映射到同一段落，明确每项信息的首次表达位置。功能单元与写作 Agent 的数量不决定成稿段数。
- W2 只写本段负责的信息，不为使局部文字独立成篇而重复全文目的、已定义符号或解释边界。
- W3 对整合稿做删减：能删除或合并且不损失独立必要信息的句子，应删除或合并；不能仅将各 Agent 的文字顺次拼接。
- R 同时检查完整和简洁。信息可由公式与邻近文字共同传达；不要求每个检查项都有独立句子，不因缺少教程式推导要求扩写。

最终正文不含检查编号、信息对应表、素材来源记录、Agent 分工或审核说明。本文件是流程配置；运行中仍维护素材文档和结果文档两份工作文档。
